> دائم وتقدّم وتنبيهات … لا أريد أن ينتهي التقدّم بانتهاء الـ90 يومًا،
> أريد أن يكون الإبداع مستمرًّا … اتقان، عمل دائم، ليس تلفيقًا … بطريقة لم
> يسبق لها مثيل.»

## 0. المبدأ — بلا نهاية

- **لا «90 يومًا» كعدّاد تنازلي.** `dayIndex = today − startDate` غير محدود.
  «اليوم» = اليوم دائمًا.
- الـ90 يومًا = **دورة (cycle)** — علامة فارقة ناعمة. عند حدّ كل دورة:
  طقس **مراجعة** (تأمل + تعديل المحاور/الفترات + ترحيل السلاسل). الدورات
  **نقاط تطوّر** لا نهايات — «الإبداع مستمرّ».
- التقدّم = **نوافذ متدحرجة** (اليوم / 7 / 30 / منذ البداية) + **سلسلة**
  (أيام متتالية فوق العتبة، مع **يوم سماح أسبوعي** فلا يُصفّرها خطأ واحد) +
  **زخم كل محور** (إنجاز حديث مُرجّح).
- **تنبّؤ** (اتجاه 2026): تحذير حين يهبط زخم محور
  («محور Python هبط 3 أيام — انتبه»). بحث UCL: تكوين العادة ~66 يومًا لا
  21 ولا 90 → التصميم مرن، لا «رسوب» من يوم فائت
  ([Reclaim](https://reclaim.ai/blog/habit-tracker-apps),
  [State of Habit Tracking 2026](https://habit-streak.com/en/blog/habit-tracking/state-of-habit-tracking-2026)).

**23 فترة زمنية** (`📅 الجدول اليومي` — الوقت · النشاط · المحور · محور
مُتتبَّع؟): فجر/روحي → حفظ القرآن(quran) → رياضة/صحة → فطور/حياة →
كتاب صوتي(books) → Python(coding) → ERP(erp) → استراحة/تنظيم →
إنتاج محتوى(social) → ظهر/روحي → Microworkers(micro) → تفسير(quran) →
وظائف(jobs) → عصر/روحي → كتاب ثانٍ(books) → مشروع ERP(coding) →
مغرب/روحي → تحرير فيديو(social) → عشاء/حياة → مراجعة الحفظ(quran) →
ورد مسائي/روحي → تدوين الإنجازات/تنظيم → تحضير الغد + نوم/نوم.
(الفترات بلا محور مُتتبَّع — روحي/صحة/حياة/نوم/تنظيم — تدخل نسبة اليوم

## 3. التفاعل ثلاثي الأبعاد (يعيد استخدام `quran-premium-3d-ui`)

- **بطاقة «الآن»**: الفترة الحالية، كبيرة، تتنفّس؛ spring‑in عند تغيّر
  الفترة؛ نقر لإكمال → `HapticFeedback.mediumImpact` + الحلقة تمتلئ بنابض؛
  «تفتّح» هادئ بلا استعراض.
- **حلقة التقدّم**: `CustomPaint` + محاكاة نابض (`AppMotion`)، نسبة اليوم في
  المركز؛ ضغط مطوّل → النوافذ المتدحرجة تتوسّع.
- **الخريطة الحرارية اللانهائية**: شريط شهور أفقي من نقاط الأيام (تدرّج
  أخضر بنسبة اليوم)، اليوم ينبض؛ يتمرّر للخلف حتى البداية، الأمام «غدًا»
  شبح.
- **ورقة المراجعة الأسبوعية**: تصعد من شريط الأسبوع؛ «ملخص الأسبوع».
- بلا حزم جديدة — `depth.dart` / `motion.dart` + `HapticFeedback` من
  `flutter/services`
  ([micro‑interactions](https://medium.com/@flutter-app/animations-micro-interactions-in-flutter-make-your-ui-delightful-592fb9da6e11),
  [physics sim](https://flutter.dev/docs/cookbook/animation/physics-simulation)).

## 4. التنبيهات (تكيّفية)

`NotificationService` قائم (قنوات لكل مجال، `zonedSchedule`). نضيف قناة
`life_slots`:
- تذكير لكل فترة عند `start_min` لفترات **اليوم** (يُعاد جدولته كل فتح +
  منتصف الليل): «⏰ 08:30 — 💻 Python / برمجة (اليوم N)».
- **موجز الصباح** (05:00): مهام MIT الثلاث + فترات اليوم.
- **حاسب نفسك ليلًا** (21:30): «أنجزت X/23 اليوم. اكتب ملاحظتك وهدف الغد.»
- تكيّفي (L4+): إزاحة تذكير الفترة نحو وقت إنجازها الفعلي (من `done_at`).

2. **قوالب اليوم** — يوم عمل / جمعة / راحة / سفر؛ الجدول المعروض يتكيّف حسب نوع اليوم (افتراضي لكل يوم أسبوع + تجاوز لتاريخ بعينه). **معماريّة كاملة (٢٠٢٦-٠٩-١٢)**، مبنيّة على النمط المعياريّ لتكرار الفعاليات (iCalendar RFC 5545: قاعدة تكرار افتراضية + استثناءات بالتاريخ تطغى عليها — [Medium: Recurring Calendar Events DB Design](https://medium.com/@aureliadotlim/recurring-calendar-events-database-design-dc872fb4f2b5)، [DHTMLX Scheduler](https://docs.dhtmlx.com/scheduler/recurring_events.html)) — نفس المبدأ المُطبَّق هنا بأبسط صورة ممكنة: **لا تُخزَّن كل نسخة يوم على حدة**، بل قاعدة (افتراضي لكل يوم أسبوع) + استثناء (تاريخ محدَّد) يُحسَبان وقت العرض:
   - **مخطّط v65 (كان مخطَّطًا v64 وقت الكتابة، لكن v64 حُجز فعليًّا لإصلاح حواشي الألبانية/الأوزبكية في نفس اليوم — تحقَّق من رقم النسخة الفعلي في database_helper.dart قبل التنفيذ)** (إضافي، بلا كسر): `life_day_templates(key TEXT PRIMARY KEY, label TEXT, icon TEXT, sort INTEGER)` — يُزرَع بأربعة: `work`(يوم عمل، الافتراضي الحالي)، `friday`(جمعة)، `rest`(راحة)، `travel`(سفر). `life_slots` يكسب عمودًا `template_key TEXT NOT NULL DEFAULT 'work'` (فترات القالب الحالي كلها `work` تلقائيًّا عبر `DEFAULT` — ترحيل صفري الخطر). `life_day_type_defaults(weekday INTEGER PRIMARY KEY, template_key TEXT)` — يُزرَع بصفٍّ واحد فقط: `(5, 'friday')` (الجمعة=٥ بترقيم `DateTime.weekday % 7` المُستخدَم أصلًا في المشروع)، الباقي `work` ضمنيًّا (غياب الصفّ = افتراضي). `life_day_overrides(date TEXT PRIMARY KEY, template_key TEXT)` — فارغ عند الزرع، يُملأ يدويًّا (سفر/عطلة).
   - **دالة الحلّ الوحيدة** (نقيّة، بلا حالة): `templateForDate(date) = life_day_overrides[date] ?? life_day_type_defaults[date.weekday] ?? 'work'` — التاريخ المحدَّد يطغى دائمًا على يوم الأسبوع، تمامًا كنمط RFC 5545. `LifePlanRepository.todaySlots()`/`todayProgress()` يستدعيانها أولًا ثم يُصفّيان `life_slots WHERE template_key = ?` بدل التحميل غير المشروط الحالي.
   - **فترات قالب الجمعة**: تُبنى بنسخ فترات `work` ثم تعديلها يدويًّا (لا توليد آليّ) — الفرق الحقيقي الوحيد المعروف: فترة الظهر تصبح «الذهاب لصلاة الجمعة + الاغتسال» (بلا محور مُتتبَّع، كفترات «روحي» الأخرى)، وفترات العمل (ERP/Microworkers) تُقصَّر أو تُحذَف حسب عادة إسماعيل الفعلية — **يُسأل إسماعيل صراحةً عن التفاصيل الدقيقة قبل الزرع النهائي، لا تُخمَّن**؛ `rest`/`travel` تُبنى بنفس الأسلوب (تقليص جذريّ للفترات المُتتبَّعة، إبقاء الروحيّ/الصحيّ فقط).
   - **الواجهة**: زر ⚙ الموجود في «اليوم» يكسب قسمًا ثالثًا «قوالب اليوم» (بجانب المحاور/الفترات الحاليين في `life_plan_edit_screen.dart`) — قائمة القوالب الأربعة (كل قالب يُفتح على تبويب الفترات الحالي مفلترًا بـ`template_key`)، ثم شبكة أيام الأسبوع السبعة لضبط `life_day_type_defaults` (اختيار قالب لكل يوم من قائمة منسدلة)، ثم قائمة الاستثناءات بالتاريخ (`life_day_overrides`) بزرّ «أضف استثناء» (منتقي تاريخ + قالب) — يطابق تمامًا نمط "override a single occurrence" في تقاويم Google/Outlook المرجعيّة أعلاه، لا تصميم جديد مُخترَع.
   - **الترتيب الفعليّ**: v65 المخطّط (بلا واجهة) → `templateForDate` + تحديث `todaySlots`/`todayProgress` (بمجرّد `work` فقط، يجب أن يبقى كل شيء كما هو تمامًا، اختبار انحدار أولًا) → قوالب `friday`/`rest`/`travel` (بعد سؤال إسماعيل) → واجهة الإعداد → `life_day_type_defaults` مزروعة → اختبار حيّ عبر تغيير `life_meta` مؤقّتًا لمحاكاة يوم جمعة.

   أسبوعي بـ«٢/٥ هذا الأسبوع»، معالم) يظهر فقط إن كان السجلّ غير فارغ. المحرّر:
   تبويب ثالث «المهام» + `_TaskForm`. ١٠ مفاتيح `life_*` ×13. ٧ اختبارات repo
   (27/27). المحاكي: ترحيل v58→v59 نظيف، البطاقة تُرسم، النصّ يُحفَظ والعدّاد
   يتحدّث، التأشير يشطب.

**ب · تتبّع ديناميكي**
4. **إتمام جزئي + كمية** ✅ — مخطّط **v60**: `life_slots.qty_target`/`qty_unit`
   + `life_tasks` مثلها، `life_day_slots.progress`(0..1)/`qty`،
   `life_task_log.progress`/`qty`. `progress` فارغ ⇒ يُقرأ `done` القديم

   `LifeDayProgress.slotProgress`/`slotQty` + `percent` = **متوسّط كسور كل
   فترة**، `LifeDayTasks.dailyProgress`/`dailyQty`. الريبو: `slotStates`/

   كامل) للبنود العادية + `_QtyStepper` (`− n/target وحدة +`) للبنود الرقمية
   في «اليوم»؛ `_QtyTargetField` (عدّاد هدف + حقل وحدة) في نموذجَي الفترة
   والمهمة اليومية. ٤ مفاتيح `life_*` ×13. ٦ اختبارات repo (32/32).
5. **تسجيل فعلي بلمسة** — وقت الإنجاز الحقيقي (`done_at` مخزَّن) + سطر «ماذا أنجزت» اختياري → يوميّات.
