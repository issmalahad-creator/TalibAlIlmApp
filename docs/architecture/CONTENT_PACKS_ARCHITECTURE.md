## 1. ما تعلّمناه من الخارج (مساعد لا موجّه)

| الممارسة | المصدر | ما نأخذه |

لسنا على Google Play، و GitHub Releases هو «CDN» المجاني المتاح (حدّ الملف 2 GB، بلا حدّ للتنزيل). نبني المبادئ نفسها فوقه.

## 2. الواقع الحالي

- `QuranCorpusDownloadService`: مربوط بإصدار واحد `corpus-v1` (رابط ثابت)، كتاب = ملف `<id>.json.gz`. لا manifest، ولا sha256، ولا استئناف، ولا إلغاء أو إيقاف، ولا حذف، ولا وعي بالشبكة. الملف يُكتب مباشرة، فإن انقطع يبقى نصف ملف يُقرأ كأنه كامل.
- `askCorpusDownload`: `AlertDialog` عام — «تنزيل؟ الحجم X» بلا اسم الكتاب ولا مؤلفه ولا نوع الشبكة ولا المساحة المتاحة.
- التقدّم: سطر نسبة مئوية داخل اللوحة، بلا MB ولا وقت متبقٍّ ولا إلغاء.
- لا شاشة تعرض ما نُزّل ولا كم يشغل.
- ما يبقى داخل lite ويُراد نقله (S4/S5): التفاسير القديمة غير الأساسية ≈35 MB، وcorpus الثقيلة ≈40 MB.

## 3. التصميم

### 3.1 أربع طبقات، ولكل طبقة مسؤولية واحدة
```
GitHub Release  packs-v1          ← النشر: tool/publish_packs.py + gh
  packs_manifest.json + ملفات الحزم (أسماء بإصدار، لا تتغيّر)
        │ HTTPS (ETag للـmanifest، Range للملفات)
ContentPackEngine (Dart)          ← CP1: manifest، طابور، تنزيل مستأنف، sha256، rename ذري، حالات
        │
Installers                        ← CP4/CP5: ماذا يعني «مثبّت» لكل نوع (ملف في الكاش / بذر جدول DB)
        │
UI                                ← CP3: ورقة التنزيل، تقدّم في المكان، «التنزيلات والمساحة»
```
الميزة تسأل **«هل حزمتي مثبّتة؟»** (`ContentPacks.status(id)`)، لا «هل أنا lite؟». نسخة full تعلن حزمها «مضمّنة» فتُعامل كمثبّتة بلا شبكة.

### 3.2 الـ manifest (مصدر الحقيقة)
```json
{ "schema": 1, "generated": "2026-09-27", "base": "https://github.com/…/releases/download/packs-v1/",
  "packs": [ { "id": "tafsir.ibn_kathir", "kind": "tafsir", "version": 1,
               "title": {"ar": "تفسير ابن كثير", "en": "Tafsir Ibn Kathir"}, "author": {"ar": "…"},
               "files": [ { "name": "tafsir.ibn_kathir.v1.jsonl.gz", "bytes": 4123456, "sha256": "…" } ],
               "installer": "legacy_tafsir", "license": "…" } ] }
```
- نسخة صغيرة منه مضمَّنة في التطبيق (`assets/packs/packs_manifest.json`، بضعة KB) كي تُعرض الأحجام بلا اتصال. الأحدث يُجلب بـETag عند فتح «التنزيلات» أو قبل التنزيل، لا عند الإقلاع.
- ملف منشور لا يُستبدل أبدًا؛ التحديث = `version` جديد + اسم ملف جديد → الحزمة المثبّتة تُظهر «تحديث متاح».

### 3.3 آلة حالات الحزمة
`notInstalled → queued → downloading(received,total,speed) ⇄ paused → verifying → installing → installed`
ومن أي حالة إلى `failed(reason)` حيث السبب واحد من: `offline`، `noSpace`، `checksum`، `notFound`، `server`. كل سبب له جملة مترجمة وزر «أعد المحاولة». وتظهر `waitingForWifi` حين اختار المستخدم «عند توفر Wi-Fi»، و`updateAvailable` بعد التثبيت.

### 3.4 محرك التنزيل (CP1)
- ملف `.part` + `Range: bytes=N-` + `If-Range` (ETag)؛ رمز 206 يُكمل، و200 يبدأ من الصفر.
- SHA-256 تدريجي أثناء الاستلام؛ عند الاكتمال مقارنة، ثم `rename` ذري إلى الاسم النهائي. النصف لا يُقرأ أبدًا.
- طابور بتنزيل واحد في الوقت نفسه (الهاتف والشبكة لا يستفيدان من التوازي)؛ الأولوية لما طلبه المستخدم الآن على «حمّل الكل».
- قبل البدء: فحص المساحة الحرة (حجم الحزمة ×2 للفك).
- الشبكة (`connectivity_plus` الموجود): على بيانات الجوال وحجم > 20 MB → تُسأل صراحة، أو «انتظر Wi-Fi». عند عودة Wi-Fi تُستأنف تلقائيًا ما دام التطبيق مفتوحًا.
- الاستئناف بعد إغلاق التطبيق: ما كان في الطابور يُستأنف عند الفتح التالي كمهمة `BootScheduler` بأولوية منخفضة و`afterHome`، على Wi-Fi فقط. التنزيل في الخلفية بعد الإغلاق غير مشمول في v1 (يحتاج WorkManager)، ويُقال ذلك بصدق.
- لا يرمي استثناءً أبدًا للواجهة: كل فشل يتحول إلى حالة `failed(reason)`.

### 3.5 الواجهة (CP3) — ما يحلّ «البدائية»
1. **ورقة التنزيل** (bottom sheet بدل AlertDialog): اسم الكتاب ومؤلفه، ما الذي ستحصل عليه بجملة، الحجم، نوع الشبكة الحالي («أنت على Wi-Fi» / «بيانات الجوال — X MB»)، المساحة الحرة. الأزرار: «حمّل الآن» · «عند توفر Wi-Fi» (على الجوال فقط) · «ليس الآن».
2. **التقدّم في المكان:** شريط + «4.1 من 12.3 MB · دقيقة متبقية» + إيقاف/إلغاء، مع رسائل IF المرحلية («جاري التحقق…»، «جاري التجهيز…»). عند الاكتمال يظهر المحتوى مكان الشريط مباشرة، بلا رجوع ولا إعادة فتح.
3. **«التنزيلات والمساحة»** (من الملف الشخصي ومن منتقي التفاسير): مجموعات (تفاسير · ترجمات · علوم القرآن · صوت)، ولكل حزمة الحجم والحالة وزر واحد مناسب (تنزيل / إيقاف / حذف ويوفّر X MB / تحديث). في الأعلى المجموع المستخدم والمساحة الحرة، وزر «حمّل الأساسيات على Wi-Fi».
4. **منتقي التفاسير:** كل تفسير عليه شارة «على جهازك ✓» أو «⬇ 4.1 MB»، فيعرف المستخدم قبل أن يختار.
5. **حالات صادقة:** لوحة لم تُحمَّل حزمتها تقول «هذا المحتوى غير محمَّل — 3.7 MB» مع زر، لا فراغ ولا رسالة «لا توجد بيانات».
كل النصوص عبر `basicText` بـ13 لغة، وتوقيتات IF (0/300/800 ms).

### 3.6 النشر عبر GitHub (CP2)
`tool/publish_packs.py`: يجمع الملفات من `assets/…` حسب جدول الحزم، ويسمّيها بالإصدار، ويحسب الحجم وsha256، ويكتب `packs_manifest.json` (وينسخ لقطة منه إلى `assets/packs/`)، ثم `gh release upload packs-v1 … --clobber` للـmanifest فقط. الملفات الموجودة لا تُرفع مرتين. قبل الرفع: فحص الترخيص من `QURAN_SOURCES_AND_LICENSES.md` — ما لا يُسمح بنشره علنًا لا يدخل الحزم (المستودع عام).

### 3.7 الترحيل
`QuranCorpusDownloadService` (تفاسير/ترجمات لكل كتاب من `corpus-v1`) يصبح نوع حزمة `book` فوق المحرك نفسه، ويبقى مسار الكاش القديم مقروءًا كي لا يُعاد تنزيل ما نزّله المستخدم سابقًا. الـ API الخارجي (`QuranBookCache`) لا يتغيّر.

## 5. بوابة الخفة (lightweight-feature-rules)
1. لا عمل عند الإقلاع (سوى استئناف طابور معلّق، `afterHome`، على Wi-Fi). 2. كسول. 3. البيانات تنتقل من APK إلى GitHub؛ ما يُضاف للتطبيق manifest بضعة KB. 4. الذاكرة: التنزيل تدفّقي إلى ملف ولا يُحمَّل كاملًا في الذاكرة (خلافًا للحالي `BytesBuilder`). 5. sha256 التدريجي والفك في `compute`. 6. بذر الجداول عبر المثبّت على دفعات. 7. يُحمَّل بفعل المستخدم. 8. يُحرَّر بالحذف من «التنزيلات». 9. لا يمسّ الرئيسية. 10. يسأل فقط من شاشة فتحها المستخدم، مع الحجم والشبكة.
