# خطة نظام هندسة المعرفة الشرعية في طالب العلم

> **2026-09-26 — رؤية عامة فقط.** نموذج البيانات والتجربة الأولى هنا صُحِّحا في [`docs/quran/USUL_TAFSIR_TREE.md`](quran/USUL_TAFSIR_TREE.md) §9 (لا جداول موازية، لا درجات ثقة رقمية، مفردات العلاقات من العلم نفسه). عند التعارض يُعتمَد ذلك الملف.

## 1. المقدمة

هذه الخطة تخرجنا من فكرة "خريطة ذهنية جميلة" إلى نظام معرفي حقيقي قابل للتوسع داخل التطبيق، ويستفيد من ما تم بناؤه فعليًا في المشروع حاليًا.

الغرض الأساسي هو بناء نظام يربط بين:

- النص الشرعي
- المصدر
- العلاقة بين المفاهيم
- الدليل
- الخلاف
- الاسترجاع
- مستوى الطالب
- التقييم والنتيجة

بدل أن يكون مجرد عرض بصري لا علاقة له بالمنطق الشرعي أو تعليم الطالب.

مبدأ المشروع هو:

> العرض البصري هو واجهة فقط، بينما القلب الحقيقي هو Knowledge Graph (شبكة المعرفة) + Study Intelligence (ذكاء الدراسة).

## 3. هدف النظام

### 3.1 الهدف العام

بناء نظام داخل التطبيق يمكنه:

- تمثيل المفاهيم الشرعية كعقد، لا كنصوص منفصلة
- ربط كل مفهوم بالمصدر، الدليل، المثال، والخلاف
- إنشاء شبكة مترابطة بين:
  - القرآن
  - التفسير
  - الحديث
  - العقيدة
  - الفقه
  - المصطلحات
  - الملاحظات
- تمكين الطالب من الاسترجاع بدل من القراءة فقط
- دعم التعلم التكيفي حسب مستوى الطالب

### 3.2 الهدف من وجهة الطالب

- يرى العلاقة بين المفاهيم وليس مجرد نصوص
- يفتح مفهومًا فيكتشف أصوله وأدلته ومصادره
- يراجع ما حفظه بناءً على استرجاع وليس على خريطة ثابتة
- يتعلم من النصوص الشرعية بطريقة منظمة ومبنية على التوثيق

---

## 4. المبدأ الأساسي الذي سنبنيه

### 4.1 لا نصنع نظامًا للعرض فقط

ليس كافياً أن يكون هناك شجرة أو خريطة جميلة. يجب أن يكون هناك:

- عقدة معرفية
- علاقة بين العقد
- مصدر
- المستوى التعليمي
- الحالة الحالية للطالب

### 4.2 لا نعتمد على AI كوسيلة أساسية

النظام يجب أن يكون:

- قابل للتفسير
- قابل للتوثيق
- قابل للشرح
- يعتمد على قواعد واضحة لا على توليد عشوائي

أي أن كل نتيجة تُظهرها التطبيق يجب أن يكون لها:

- مصدر
- توثيق
- سياق
- شرح
- درجة ثقة

## 5. النمذجة الأساسية

## 5.1 العقدة (Node)

كل مفهوم أو نص أو مصدر أو مسألة يكون عقدة.

### مثال لأنواع العقد

- Concept: النية
- Ayah: الآية 286 من البقرة
- Hadith: حديث جبريل
- Book: العمدة أو الأربعون النووية
- Topic: العقيدة، الفقه، الآداب
- Question: سؤال استرجاع

### الحقول الأساسية للعقدة

```json
{
  "id": "concept_001",
  "title": "النية",
  "type": "concept",
  "summary": "قصد القلب في العمل",
  "detail": "...",
  "domain": "aqeedah|fiqh|tafsir|hadith",
  "status": "draft|verified|reviewed",
  "created_at": "2026-09-23",
  "updated_at": "2026-09-23"
}
```

---

## 5.2 العلاقة (Relation / Edge)

العلاقة هي أهم جزء في النظام، لأن العقد وحدها لا تفيد كثيرًا.

### أمثلة للعلاقات

- يشرح
- يدل على
- يوصل إلى
- يؤيد
- يخصّص
- يقيّد
- يستثني
- يُمثّل
- يتفرّع من
- مرتبط بـ
- يختلف فيه
- يشرح عبر

### مثال

```json
{
  "from": "concept_001",
  "to": "hadith_010",
  "relation": "يدل على",
  "strength": 0.92,
  "source_id": "source_ref_001",
  "note": "حديث: إنما الأعمال بالنيات"
}
```

---

## 5.3 المصدر (Source)

كل معلومة تحتاج مصدرًا.

### حقول المصدر

```json
{
  "id": "source_ref_001",
  "name": "صحيح البخاري",
  "source_type": "hadith",
  "author": "محمد بن إسماعيل البخاري",
  "reference": "كتاب الإيمان، باب النية",
  "license": "public_domain_or_approved",
  "classification": "VERIFIED",
  "confidence": 0.96,
  "retrieved_at": "2026-09-23"
}
```

هذا مهم جدًا لأننا لا نريد أن يخرج النظام بمعلومات بلا سند.

---

## 5.4 التوثيق (Provenance)

هذا عنصر أساسي جدًا في المشروع الشرعي.

نقسم التوثيق إلى:

- توثيق المصدر
- توثيق الدلالة
- توثيق السياق
- توثيق العلاقة بين العقد

### مثال

```json
{
  "claim": "النية تؤثر في قبول العمل",
  "provenance": {
    "source_authority": 0.95,
    "directness": 0.90,
    "context_fit": 0.96,
    "independent_support": 0.88
  }
}
```

### قاعدة مهمة

لا نقول: "هذا صحيح بنسبة 92%" فقط.

بل نقول:

- درجة توثيق المصدر
- قوة الدلالة
- مناسبة السياق
- دعم مستقل

وهذا يبعد المشروع عن أي خطأ يُصنف على أنه حكم فاحش أو رأي غير موثوق.

## 9. التصميم الانساني للمستخدم

نريد واجهة تجمع بين:

- احترافية
- بساطة
- عمق
- تمييز بين النص والسند والترابط

  - العنوان
  - الملخص
  - الدليل
  - العلاقة
  - الخلاف
  - السؤال التالي
- barrel من السرد الشرعي:
  - نص
  - شرح
  - مصدر
  - مثال
  - سؤال
- زر "توسيع" و "تلخيص"
- زر "أظهر العلاقات"
- زر "استرجاع"

### قاعدة هامة

لا تعرض للمستخدم كل المعلومات دفعة واحدة.

العرض يكون:

1. المفهوم
2. روابطه
3. مصادره
4. الخلاف
5. سؤال الاسترجاع

وهكذا نبتعد عن الازدحام.

## 15. المعايير المهنية للنجاح

### نجح النظام إذا:

- كل مفهوم له مصدر واضح
- كل علاقة لها دليل أو توثيق
- كل نقطة في الخريطة يمكن تتبعها إلى أصلها
- الطالب يستطيع أن يفتح مفهومًا ويعرف: ما هو؟ من أين؟ ما علاقته؟ ما الخلاف؟ كيف يراجع؟
- الواجهة مشتقة من شبكة المعرفة وليست مجرد عرض تصويري

---

## 16. الخلاصة

الفكرة الصحيحة ليست مجرد بناء خريطة ذهنية بأسلوب جميل، بل بناء منظومة معرفة شرعية متسلسلة وموثقة وقابلة للاسترجاع.

### التغيير الحقيقي هو:

من:

- خريطة جميلة

إلى:

- نظام معرفي قابل للتعلم، التوثيق، الاسترجاع، والتكيّف

وهذا هو ما يميز طالب العلم عن التطبيقات التقليدية.

---

## 17. التوصية النهائية

نبدأ بـ:

1. تعريف Schema
2. نموذج العقدة والعلاقة
3. ربطه بالمنطقة الحالية من المشروع
4. إنشاء Pilot صغير
5. تقييمه
6. توسيعه تدريجيًا

هذا هو الطريق الصحيح، والنتيجة ستجعل المشروع ينمو كمنظومة تعليمية حقيقية لا مجرد شاشة أو فكرة جمالية.

## 18. الرمز التطبيقي النهائي

لن نبدأ من النهايات، بل من هذه القاعدة:

```text
Knowledge Graph
   + Source Provenance
   + Relationship Logic
   + Learning State
   + Adaptive Retrieval
   + Quran Integration
 = Islamic Study Intelligence System
```

وهذا هو المسار الذي سنتبعه في التطبيق.
